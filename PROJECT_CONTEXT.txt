1. PROJECT OVERVIEW
OpenView is an open source, fast, clean, and sleek offline file viewer for Android.
- Core Promise: NO ads, NO accounts, NO analytics, NO tracking, and NO internet permission.
- Purpose: Replace ad-ridden, slow document viewers with a stable, lightweight utility prioritizing speed over feature bloat.
- Phase 1 Scope: Fast viewing of TXT, Code files (.py, .kt, .java, .cpp, .js, .html, .css, .json, .xml, .md), PDF (android.graphics.pdf.PdfRenderer), DOCX (structured readable view), and Images (.jpg, .jpeg, .png, .webp, .bmp via BitmapFactory with inSampleSize downsampling and pinch/pan zoom). Legacy .doc shows a friendly "not supported yet" screen. System "Open with" intent filter, Recents list via Room, and Settings via DataStore.

2. TECH STACK
- Language: Kotlin 2.2.10 (Apache 2.0)
- UI Toolkit: Jetpack Compose with Material 3 (BOM 2024.09.00) (Apache 2.0)
- Navigation: androidx.navigation:navigation-compose:2.8.9 (Apache 2.0)
- Architecture/State: androidx.lifecycle:lifecycle-viewmodel-compose:2.8.7 (Apache 2.0)
- Local Persistence: androidx.room (runtime/ktx/compiler 2.7.0 via KSP 2.3.5) (Apache 2.0)
- Preferences: androidx.datastore:datastore-preferences:1.1.7 (Apache 2.0)
- Asynchronous Runtime: kotlinx-coroutines-android:1.10.2 (Apache 2.0)
- Minimum SDK: 26 (Android 8.0 Oreo) | Target SDK: 36 (Android 16)
- Dependency Management: Gradle Version Catalog (libs.versions.toml)

3. ARCHITECTURE
- MVVM with Unidirectional Data Flow (UI -> Event -> ViewModel -> StateFlow -> Compose UI).
- Layered Separation:
  - UI Layer: Screen composables consuming ViewModel UI state with collectAsStateWithLifecycle.
  - Reusable Components: Modular widgets in ui/components/ (OpenViewTopAppBar, FileCard, SettingsRow, ViewerErrorView, DraggableFastScrollBar, PinchZoom).
  - Navigation: Centralized NavGraph with sealed Screen destinations; OpenFileSession state holder avoids string URI route bugs.
  - Data Layer: Room Database for recent files history & scroll positions; DataStore for settings preferences.
  - Core/Router: SAF Uri abstraction, MIME & extension type inference, magic bytes sniffing, and viewer dispatching.
- Modern Accessible Material 3 Design System:
  - Accent Color: Modern Blue (#1D63ED / AccentBlue).
  - Light mode: Soft off-white background (#F8F9FA), pure white cards/surfaces (#FFFFFF), dark gray text (#1E2022).
  - Dark mode: Deep charcoal background (#121418), dark gray cards/surfaces (#1C1F26), off-white text (#F0F2F5).
  - Geometry: Generous rounded corners (16–24dp), 56dp minimum touch targets, subtle card elevation/depth, color-coded format badges (PDF red, Word blue, Text green, Code purple).
  - Material You / dynamic color completely disabled. All color tokens centralized in Color.kt and Theme.kt.
- Strict Constraints: Zero INTERNET permission, zero external tracking dependencies, all UI strings defined in strings.xml, all dimensions in Dimens.kt.

Vertical scrolling remains handled by LazyColumn and horizontal panning by native horizontalScroll. Visible page bitmaps are re-rendered at target display width debounced by 300ms via LruCache with a safety cap of 4096px and OutOfMemoryError recovery.
69: - 2026-10-15: Reflow zoom for document viewers (DOCX, TXT, CODE): Text viewers scale typography sizes, line heights, and table cells rather than viewport transforms, preserving text sharpness and native scroll stability with scroll index/offset preservation.
70: - 2026-10-15: Static download website hosting: Vercel Root Directory = "website", so only index.html and style.css are hosted and served publicly. Zero build step, zero npm dependencies, isolating the Android app codebase from the static site.
71: - 2026-10-15: DOCX XML Parsing and Path Normalization: Standardized ZIP entry checking with path normalization (`trim().lowercase().replace('\\', '/')`) and safe XML text reading in `parseRun` to avoid `XmlPullParserException` on child nodes/comments. Added tag:FileOpen logging for size, ZIP entries, and paragraph count.
- 2026-10-15: Image Decoding & Bounds Null-Check: Fixed `ImageViewerViewModel` decode bounds handling. When `BitmapFactory.Options.inJustDecodeBounds = true`, `BitmapFactory.decodeStream()` inherently returns `null`; separated the `openInputStream(uri)` null-check from the `use { ... }` block to avoid evaluating the Elvis operator to an exception. Added bounds dimension validation (>0) with user-friendly corrupt image error (`viewer_error_image_corrupt`), dynamic `inSampleSize` computation against 4096px bounds cap, and `OutOfMemoryError` recovery (`viewer_error_image_oom`). Standardized `FileOpen` diagnostic logging across `OpenFileSession` and all viewer viewmodels.
- 2026-10-15: Direct Filesystem Document Discovery: Implemented direct java.io.File scanning on Environment.getExternalStoragePublicDirectory (Download & Documents) for supported document formats (PDF, DOCX, TXT, CODE). Removed MediaStore queries and scoped permissions using READ_EXTERNAL_STORAGE (maxSdkVersion 29) and MANAGE_EXTERNAL_STORAGE (tools:ignore="ScopedStorage"). Maintained strict zero INTERNET policy and offline-only processing.
